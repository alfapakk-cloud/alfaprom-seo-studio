# Generation and preview 1.6.1

- During image creation the label is «Прогресс изображений:». Its estimate is calculated from the completed image count and the current image stage, rather than displaying the whole generation workflow percentage under an image-specific label.
- «Проверить статью после генерации по 23 критериям» is enabled by default, persisted in the article's generation options and disabled while a task is running. The choice is respected when resuming a paused image queue. Disabling it skips the separate post-generation audit request; the 23 writing requirements remain in the prompt. An explicit later audit is still available. Skipping does not create an AI report or approve publication.
- General preview chooses an unapplied, current generation draft automatically. Explicit current/draft selection remains available. The publication check and current-article export preview explicitly use the applied current article.
- Preview uses the real saved WebP assets as temporary in-memory data URLs inside the existing opaque sandbox. It retains the cover and per-section anchors, deduplicates file requests, waits for the image batch without rebuilding the whole preview on every file, and ignores late responses after a version switch. Image binaries are not added to project JSON or saved article HTML. Missing files have a status and retry action.
- Apply is retained and explained in the draft and preview. It makes the reviewed generation draft the current text, SEO fields and images for the editor, quality checks and export, while preserving the previous version. Applying is separate from publication. It does not cause another generation request.

Validation: 137 isolated browser scenarios, including the existing 127 checks plus defaults, opt-out request routing, resume choice, explicit manual audit, accurate image progress, draft selection, actual WebP decoding and anchor placement, late response isolation, and apply-to-editor/export behavior. JavaScript syntax and exact unchanged SEO-plan/strategy source regions were checked. The browser harness uses an independent storage key and simulated GPT responses. No live model request is needed for these checks.

The helper backend, protocol 8, ChatGPT subscription authentication, GPT-6.1 Sol High selection and existing WebP libraries are unchanged. Both archives include the same UI update; the existing native launcher implementation is repackaged and signed. User articles, browser profiles, credentials and Application Support are excluded from the release.
