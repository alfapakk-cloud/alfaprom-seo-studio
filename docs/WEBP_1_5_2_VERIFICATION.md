# Исправление WebP — α SEO 1.5.2 / протокол 8

26.10.2026 пользователь сообщил: текст 1937 знаков сохранился, очередь остановилась на 0/3 с ошибкой браузерного WebP-кодирования. Ранее тест выполнялся в браузере, где Canvas.toBlob поддерживал WebP; это не покрывало браузеры, возвращающие PNG.

Теперь при отсутствии WebP браузер передаёт ограниченный RGBA-буфер уже кадрированного изображения локальному помощнику. Включённые libwebp/libsharpyuv кодируют настоящий WebP; браузер запрашивает и отображает сохранённый файл, а не исходный RGBA. Никакой модели или API для конвертации не вызывается. Границы Host/Origin/сеансового ключа прежние; размеры и длина буфера проверяются до вызова кодировщика.

Проверено:

- 112/112 браузерных сценариев, включая принудительный возврат PNG вместо WebP из Canvas.toBlob.
- 31 Python-тест: настоящее кодирование и чтение WebP, полный буфер обложки 1680×720 в существующем лимите HTTP, отклонение повреждённых/несоответствующих буферов до загрузки библиотеки.
- Отдельная очередь без вызовов GPT, с принудительно отключённым WebP в браузере: текст → три сохранённых WebP → оценка. Все три картинки загрузились, показали реальные размеры, ошибок нет. Для теста транспорта использовалась одна контрольная исходная картинка; это не тест различия сюжетов.
- Нативная сборка включает кодировщик и его зависимость, лицензия сохранена. Пользовательский текст не заменялся тестовым.

Нужен один перезапуск установленного помощника, потому что процесс предыдущей версии не умеет кодировать RGBA. После обновления страницы сохранённый черновик продолжается кнопкой «Продолжить WebP»; генерацию текста повторять не нужно. Пока новый протокол не подключён, новые модельные запросы генератора не запускаются.
