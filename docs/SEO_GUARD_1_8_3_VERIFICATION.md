# Устойчивые точечные исправления 1.8.3

1 ноября 2026. Изменена только обработка точечных ответов в интерфейсе. Бэкенд, протокол 11, модель `gpt-6.1-sol`, reasoning High, вход ChatGPT, генерация и проверка источников побайтово совпадают с 1.8.2. Перезапуск помощника не нужен; достаточно обновить локальную страницу после окончания текущей попытки.

В схеме `patch` объект `seo` с Title, Description и H1 обязателен для любой группы критериев. В 1.8.2 возвращённое моделью изменение этих полей при исправлении других критериев отклоняло весь ответ с сообщением «SEO-поля изменены без относящегося к ним замечания». Повтор той же группы мог закончиться тем же сообщением, хотя буквальные замены основного текста были допустимы.

В 1.8.3 область прав не расширена: SEO меняется только в прежних разрешённых группах 1/5/6/21. В остальных группах клиент полностью сохраняет исходные SEO-поля, игнорирует неиспользуемые предложения модели и продолжает проверку корректного HTML-патча. Незапрошенные значения не применяются и не записываются в историю; сохраняются только имена проигнорированных полей. Промт дополнительно требует дословную копию исходного объекта SEO, включая пробелы и пустые значения, когда эти поля не входят в задание.

Некорректные запрошенные SEO-значения, неверная версия статьи, пересекающиеся/несуществующие фрагменты, исполняемая разметка, удаление изображений/якорей, чрезмерная перегенерация и запрещённые ссылки продолжают отклоняться. Разрешённые SEO-правки по-прежнему вызывают зависимую перепроверку. Если ответ содержал только лишние SEO-предложения и не исправил сам критерий, он не становится пройденным.

Рабочая группа и завершённые группы 1.8.2 совместимы с новым интерфейсом; ключ хранения проекта, fingerprint и стандарт 2 не менялись. При наличии истории интерфейс сообщает, какие SEO-поля сохранены без изменений.

Проверено 230 автономных DOM-сценариев, включая 18 новых: игнорирование лишнего SEO, сохранение пробелов/пустых полей, сохранность исходника, разрешённые изменения, строгая валидация запрошенных полей, защита HTML/версий, текст промта и полный цикл патч → зависимая проверка → готовый результат. Три сценария реального canvas/декодирования/позиции курсора в DOM-среде пропущены, как в 1.8.2. Пользовательская статья и данные его браузера не читались; реальный результат текущего запроса не объявляется проверенным.

Автопубликация в Django остаётся отдельной локальной заготовкой и в этот релиз не входит.

## Объём и продолжение без двойной работы

Прежняя проверка объёма отклоняла любой патч вне диапазона, даже если текст был за его пределами до правки. Теперь учитываются оба счётчика. Небольшие отклонения (до 300 знаков либо 5% целевого объёма, что больше, относительно прежнего отклонения) не блокируют полезную адресную правку: в очередь зависимой проверки обязательно добавляется критерий 2. В окончательную готовность статья вне выбранного диапазона не допускается — автоматическая проверка продолжает показывать проблему2. Формат и его границы автоматически не меняются.

Сильно раздувающий ответ не применяется. GPT получает один ограниченный автоматический повтор с реальными числами «было / стало / допустимо». Если ответ снова не подходит, этот пункт остаётся нерешённым, а остальные доступные задачи продолжаются. Правка самого объёма должна уменьшать прежнее отклонение; она не может считаться улучшением при увеличении отклонения. HTML не обрезается программно, целая статья не перегенерируется.

Контрольная точка различает принятый патч, ожидание проверки и полностью проверенный результат. После остановки принятый текст направляется только на оставшуюся проверку. Полностью проверенная группа может быть восстановлена и применена без нового GPT-запроса. Старый большой сохранённый патч продолжается группой не больше 3 критериев. Повторные исправления выбираются только из актуальных непройденных пунктов; зависимая перепроверка после действительных изменений остаётся обязательной.

Добавлены 10 фикстур объёма и восстановления: унаследованное отклонение, небольшой выход за границы, строгий отказ от чрезмерного роста, полезное сокращение, ограниченный повтор, отдельная коррекция объёма без повторного переписывания уже исправленного22, восстановление принятого патча только аудитом и восстановление проверенного результата без GPT.
