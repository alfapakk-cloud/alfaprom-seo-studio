# Shared quality report 1.7.2

Previously the generated draft's 23-criterion audit appeared as an expanded summary in Structure, while Quality displayed the current article. Users could reasonably conclude that the audit was missing or inconsistent. The saved draft report itself and its transfer on Apply already existed; this change makes the version selection explicit.

Quality now defaults to a valid unapplied generated draft, with a clear New variant / Current article selector. Both views use the same outcome, issues, criteria and facts renderers. Draft mode displays the stored audit, individual reasons and source evidence without copying its decisions onto the current article. It offers preview, draft audit and Apply. Editing decisions, running current-article revision and final publication approval are available on the current version after Apply. Existing automatic and human evidence requirements remain intact.

Structure has a compact summary and a button opening all 23 criteria in Quality. Its counts use the saved draft report before Apply, and current decisions afterwards. The expanded duplicate generated-draft audit and redundant draft audit button were removed from Structure. No audit is automatically rerun just to view a report.

Current explicit version choice is retained while the UI refreshes; a distinct new draft resets the default selection. Stale drafts remain inspectable with a warning and blocked Apply/audit actions; auto mode selects the current article. Unchecked drafts show unverified criteria, never current-article scores. Facts expand in batches of ten with version-appropriate source data. Existing report-only updates remain available after an applied draft gets a newer audit.

Verification: all 159 isolated browser scenarios pass, including the 146 previous regressions and 13 new version/report scenarios. These cover direct report visibility, all-23 navigation, shared counters/no duplicate report, non-mutating switching, unchecked/stale drafts, current/draft action separation, fact pagination, Apply preserving report and previous version without inference, retained manual-only criteria, completion refreshing an open Quality page, and the existing Apply behavior with initially absent research. Test data and screenshot demo are isolated from user storage; no live GPT calls were sent.

The backend is byte-identical to 1.7.1 (protocol 9). Model, authentication, WebP libraries, browser storage key, user images and SEO-plan/strategy behavior are unchanged. Native app version is 1.7.2, build 13, with the prior launcher implementation and a refreshed verified signature. Both ZIPs contain only program files/libraries/licenses and documentation. A running 1.7.1 helper reads the new UI resources per request, so only page refresh is required.
